# Postman

> Postman is an AI-native API engineering platform that helps developers and their AI agents design, develop, test, document, govern, manage, and distribute APIs and services. The platform enables teams to move from development to production faster, with higher accuracy and fewer tokens. Coding agents use the Postman CLI, agent skills, plugins, and the Postman MCP Server to discover, test, mock, and monitor APIs, while the Context Graph grounds their work in a map of an organization's APIs, collections, and relationships. Postman Enterprise adds API cataloging at enterprise scale, and the Postman AI Stack extends the platform with Fabric, Astro, Fern, and Passport. Postman supports HTTP, GraphQL, gRPC, MCP, MQTT, WebSockets, and other API technologies.

- [Set up the Postman API MCP Server](https://learning.postman.com/docs/reference/postman-api/postman-mcp-server/overview.md): Remote and local setup, Minimal/Code/Full/Learn tool configurations, OAuth and API-key auth, EU endpoints. Use when: asked how to install, configure, or authenticate the Postman API MCP Server in an IDE or agent.
- [Postman Docs MCP Server (documentation search)](https://learning.postman.com/_mcp/server): First-party MCP server endpoint providing AI-powered search over Postman documentation at learning.postman.com. Use when: asked how to give an agent or IDE direct access to Postman docs. Not for: managing collections or other workspace data; see Postman API MCP Server.
- [Third-Party MCP Server Directory](https://www.postman.com/explore/mcp-servers): Public directory of external MCP servers published by other providers. This is not a Postman MCP server. Use when: asked to find or connect to MCP servers for non-Postman tools and services. Also: MCP catalog.

## API Development and Testing

- [API Client](https://www.postman.com/product/api-client.md): Create and save API requests, send requests, inspect responses, and debug REST, SOAP, GraphQL, and other supported API protocols.
- [Collections](https://learning.postman.com/docs/use/use-collections/overview.md): Postman's core unit — saved API requests, grouped in folders and shareable, that runners, mocks, monitors, and SDK generation all operate on. Use when: asked what a collection is or how the open collection format works.
- [Collection Runner](https://www.postman.com/product/collection-runner.md): Run and automate collection workflows across HTTP, GraphQL, gRPC, and related request types.
- [Native Git](https://www.postman.com/product/native-git.md): Postman Native Git stores API collections, specs, environments, and tests as YAML files in the same Git repo as your code, so API changes are branched, diffed, and reviewed in pull requests. Native Git works with GitHub, GitLab, and Bitbucket, supports monorepos, and is available on all Postman plans, including Free.
- [Mock Servers](https://www.postman.com/product/mock-servers.md): Create mock servers from collections or specifications, configure example responses, and simulate API behavior.
- [Performance and load testing](https://www.postman.com/product/performance-testing.md): Generate load from cloud infrastructure and read latency and error curves. Also: load testing, stress testing, k6 alternative, jmeter alternative.
- [Spec Hub](https://www.postman.com/product/spec-hub.md): Design, standardize, validate, and govern API specifications at scale. Also: swagger editor, openapi editor, asyncapi, spec linting.
- [SDK Generator](https://www.postman.com/product/sdk-generator.md): Generate production-ready, typed client SDKs from an API spec or Postman collection (TypeScript, Python, Java, PHP, Go, and C#). Use when: asked how to produce client libraries from a spec or collection.
- [Webhook testing](https://www.postman.com/product/webhooks.md): Spin up a persistent webhook listener URL in one click and register it with any provider and capture incoming events. Also: webhook tester, ngrok alternative, webhook.site alternative, requestbin.
- [Functional testing](https://www.postman.com/product/functional-testing.md): Assert on status codes, response schemas, and field values per endpoint, including error and edge cases. Use when: asked how to write or generate API test assertions. Also: pm.test, assertions, schema validation.
- [Data-driven testing](https://www.postman.com/product/data-driven-testing.md): Run one collection against every row of a CSV, JSON, or live MySQL, SQL Server, or Postgres source. Use when: asked how to run the same test across many inputs. Also: datasets, iteration data, parameterized testing.

- [Postman vs. Stoplight](https://www.postman.com/alternatives/postman-vs-stoplight.md): Design-tool comparison — Spectral governance, Prism mocks, no test runner or monitoring, and the SmartBear Swagger Studio migration path.
- [Postman vs. APIdog](https://www.postman.com/alternatives/postman-vs-apidog.md): All-in-one comparison — APIdog's visual design, Smart Mock, and on-premises option against org-wide governance, catalog, and monitoring.
